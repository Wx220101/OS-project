# 答辩 PPT 大纲 —— Orange'S B 级课程设计

> 建议 12~14 页,每页给出标题与要点;演示穿插实机截图/录屏。

---

### 第 1 页 · 封面
- 标题:**基于 Orange'S 的多级反馈队列调度器实现(B 级)**
- 选题:完成《Orange'S:一个操作系统的实现》项目要求
- 组员 / 学号 / 日期

### 第 2 页 · 选题与目标
- 参考系统:Orange'S `chapter11/c`(已是完整微内核 OS)
- B 级要求:重写/扩展核心模块,新增代码 ≥ 模块一半
- 我们的选择:**重写进程调度子系统**,并让其"可观测、可交互"

### 第 3 页 · 系统架构速览
- proc_table 统一管理任务与进程;消息传递 IPC
- 调度时机:时钟中断递减时间片,用尽则 `schedule()`
- 演示用负载:TestA/B/C(死循环,CPU 密集)+ 两个交互 Shell

### 第 4 页 · 原调度器的不足
- 单级"选剩余时间片最大者"轮转
- 无优先级分层、无防饿死、无统计、不区分计算/交互型
- 代码仅约 26 行

### 第 5 页 · MLFQ 设计(重点)
- 4 层队列,时间片 2/4/8/16 tick
- 规则:用尽降级 / 主动让出不降级 / 周期性老化提升 / 系统任务豁免
- 配图:层级 + 降级 + boost 示意

### 第 6 页 · 关键实现
- PCB 末尾新增字段(强调:汇编硬编码偏移,只能加在末尾)
- `schedule()`:高层优先 + 同层 Round-Robin
- `clock_handler()`:统计 / 老化 / 降级三段
- `sched_boost()`:防饿死

### 第 7 页 · 让调度可观测:ps + 系统调用
- 新增 `GET_PROC_INFO` 消息 → `TASK_SYS` 导出进程表
- 数据流:ps → get_procs() → send_recv → TASK_SYS → 拷回
- **现场演示 `ps`**:TestA/B/C 沉到 LVL 3,Shell/任务在 LVL 0

### 第 8 页 · Shell 增强与命令套件
- 横幅、命令历史、`history`/`clear`/`cls`/`exit` 内建
- 新命令:ps / clear / help / cat
- 控制台 `\f` 清屏
- **现场演示 `help`、`history`、`clear`、`cat readme`**

### 第 9 页 · 一个真实 Bug 的修复
- 现象:cat 后黑屏
- 调查:用脚本解析磁盘 inode,发现 `i_size` 异常
- 根因:`do_rdwt()` 读未按文件大小截断,返回整扇区残留(含 0x0C 清屏符)
- 修复:`bytes_left = min(len, i_size - pos)`

### 第 10 页 · 环境与工程化
- 中国区 WSL 403 → DISM + GitHub MSI 绕开
- 64 位适配:-m32 / -melf_i386 / -fcommon / -no-pie
- mount→mtools、CRLF 清理、QEMU 无界面截图自动化

### 第 11 页 · 工作量
- 新增/改动 ≈ 492 行;调度子系统新增 ≈ 120 行(原 ≈ 26 行)
- 改动 13 个文件 + 5 个新文件
- 满足 B 级"新增 ≥ 模块一半"

### 第 12 页 · 演示清单(现场)
1. 启动 → Alt+F2 进 Shell
2. `ps` 看 MLFQ(等几秒再 `ps` 看 CPU/WAIT 增长)
3. `help` / `history` / `clear`
4. `cat readme`

### 第 13 页 · 心得与总结
- 读懂内核数据结构是前提
- 可观测性是一等公民
- 现象 ≠ 根因,要绕到内核结构取证
- 后续可做:方向键历史回溯、更多调度算法对比
